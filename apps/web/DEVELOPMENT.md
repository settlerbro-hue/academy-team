# Разработка на другом компьютере

## Быстрый запуск

Установите Node.js 22 или новее и Git. Клонируйте приватный репозиторий либо распакуйте резервную копию. Откройте папку веб-приложения в Codex или редакторе.

```sh
npm run dev
```

Без npm: `node scripts/preview.cjs`. Откройте http://127.0.0.1:4173/. Установка зависимостей не нужна: браузерные библиотеки включены в исходники. Команды выполняются из папки с этим документом, абсолютные пути на диск D не требуются.

## Что редактировать

- `secure-dist/portal.js` — рабочий интерфейс, кабинеты и обращения к базе.
- `secure-dist/portal.css` — основной адаптивный дизайн.
- `secure-dist/material-files.js`, `material-files.css`, `pdf-viewer.js` — вложения материалов.
- `secure-dist/auth-config.js` — адрес Supabase и публичный publishable key; секретных серверных ключей здесь быть не должно.
- `supabase/migrations` — применённые миграции 001–004, `supabase/tests` — проверки серверных прав.
- `dist` — старый прототип и исходные учебные файлы, включая ключи тестов. Никогда не публикуйте этот каталог.
- `out` — безопасная публичная сборка, созданная `npm run build`.

## База и доступ

Разработка по умолчанию подключается к существующему Supabase ivlinbwuudxyjaikwaoo. Вход на другом ПК выполняется заново через Google или email. Локальные браузерные сессии и пароли переносить не нужно. Публичный ключ не выдаёт роль администратора: права проверяются на сервере.

Изменения через локальный интерфейс затрагивают общую рабочую базу. Для экспериментов со схемой используйте отдельный тестовый Supabase. Не запускайте bootstrap-owner, seed-content и миграции повторно на рабочей базе автоматически. Ключи ответов остаются в закрытой схеме academy_private.

Если вход через Google с localhost не завершился, проверьте наличие http://127.0.0.1:4173/** в разрешённых redirect URL проекта Supabase. Сам вход в опубликованный сайт не зависит от локального сервера.

## Проверка и публикация

```sh
npm run check
npm run build
```

Публикуется только `out`. Существующий Sites project_id сохранён в `.openai/hosting.json`; создание нового сайта не требуется. Для публикации из Codex используйте Sites skill и короткоживущий доступ к исходному репозиторию, затем сохранение версии и развёртывание. GitHub хранит код; отправка коммита в GitHub сама по себе сайт не обновляет.

Приватные файлы обучения уже находятся в Supabase Storage academy-assets и academy-materials. Приватный репозиторий не является резервной копией текущих записей базы: регулярные резервные копии базы и Storage настраиваются отдельно.
