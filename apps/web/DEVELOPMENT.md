# Разработка на другом компьютере

## Быстрый запуск

Установите Node.js 22 или новее и Git. Клонируйте приватный репозиторий либо распакуйте резервную копию. Откройте папку веб-приложения в Codex или редакторе.

```sh
npm run dev
```

Без npm: `node scripts/preview.cjs`. Откройте http://127.0.0.1:4173/. Установка зависимостей не нужна: браузерные библиотеки включены в исходники. Команды выполняются из папки с этим документом, абсолютные пути на диск D не требуются.

## Что редактировать

- `secure-dist/portal.js` — рабочий интерфейс, кабинеты и обращения к базе.
- `secure-dist/portal.css` — основной адаптивный дизайн.
- `secure-dist/material-files.js`, `material-files.css`, `pdf-viewer.js` — вложения материалов.
- `secure-dist/auth-config.js` — адрес Supabase и публичный publishable key; секретных серверных ключей здесь быть не должно.
- `supabase/migrations` — применённые миграции 001–007, `supabase/tests` — проверки серверных прав.
- `dist` — старый прототип и исходные учебные файлы, включая ключи тестов. Никогда не публикуйте этот каталог.
- `out` — безопасная публичная сборка, созданная `npm run build`.

## Адреса и восстановление экранов

Разделы используют адреса вида `/#/profile`, `/#/courses`, `/#/menu`. Курсы и уроки — `/#/courses/<course-id>/lessons/<lesson-id>`, материалы — `/#/library/<id>`, позиции меню — `/#/menu/<id>`. Попытки и результаты теста имеют собственные адреса `/#/tests/<test-id>/attempts/<attempt-id>` и `/#/tests/<test-id>/results/<attempt-id>`. Экраны сотрудников и редакторы менеджера тоже имеют адреса.

При обновлении загружается та же попытка из общей базы, новая не создаётся. Выбранные ответы и черновики редакторов сохраняются в sessionStorage под ключами конкретного пользователя. Они доступны в той же вкладке до завершения её сессии, при выходе из аккаунта очищаются. Это не синхронизация незавершённых ответов между устройствами. Отсчёт времени берётся из серверного started_at. Ключи ответов и персональные данные в адреса не помещаются. Доступ проверяется действующими RLS и серверными функциями.

Фото сохраняется автоматически после выбора и обработки файла; данные профиля сохраняются отдельной кнопкой. Новых прав и изменений схемы для этого обновления нет.

`node scripts/test-routing.cjs` проверяет восстановление маршрутов, сохранение идентификатора и времени попытки, ответы, результаты и недоступные адреса. Включён в npm run check.

## База и доступ

Разработка по умолчанию подключается к существующему Supabase ivlinbwuudxyjaikwaoo. Вход на другом ПК выполняется заново через Google или email. Локальные браузерные сессии и пароли переносить не нужно. Публичный ключ не выдаёт роль администратора: права проверяются на сервере.

Изменения через локальный интерфейс затрагивают общую рабочую базу. Для экспериментов со схемой используйте отдельный тестовый Supabase. Не запускайте bootstrap-owner, seed-content и миграции повторно на рабочей базе автоматически. Ключи ответов остаются в закрытой схеме academy_private.

Если вход через Google с localhost не завершился, проверьте наличие http://127.0.0.1:4173/** в разрешённых redirect URL проекта Supabase. Сам вход в опубликованный сайт не зависит от локального сервера.

## Проверка и публикация

```sh
npm run check
npm run build
```

Рабочий сайт — https://askacademy.ru/. Из корня репозитория `npm run build` формирует корневой `out`. Workflow `.github/workflows/deploy.yml` запускает проверки и сборку после push в `main`, затем отправляет только `out` на VPS под пользователем `deploy`. Публикация через прежнюю платформу больше не является способом обновления рабочего домена.

Для отправки используется секрет GitHub Actions `DEPLOY_KEY`; приватный ключ нельзя добавлять в исходники, публичную сборку или документацию. Публичный ключ должен быть установлен для пользователя `deploy` на VPS. Статус проверяйте в **Actions → Deploy**; ручной повторный запуск доступен через **Run workflow**. База и файлы в Supabase при отправке фронтенда не переносятся.

Приватные файлы обучения уже находятся в Supabase Storage academy-assets и academy-materials. Приватный репозиторий не является резервной копией текущих записей базы: регулярные резервные копии базы и Storage настраиваются отдельно.
