# Подключение регистрации и входа

Страницы доступны по `/#register`, `/#login` и `/#recover`. Пока в `dist/auth-config.js` пустые значения, реальные аккаунты не создаются. Кнопки показывают сообщение о незавершённом подключении. Демонстрация доступна отдельно по `/#demo`.

## Когда будет создан Supabase

1. Включить Email/Password в Supabase Auth, оставить подтверждение email и настроить отправку писем, ограничения частоты и требования к паролю.
2. В `dist/auth-config.js` указать Project URL и публичный publishable key (либо legacy anon key). Не использовать service_role/secret key. Этот файл доступен браузеру.
3. В Auth URL Configuration указать Site URL и разрешённые адреса возврата: `https://rvb-academy-prototype.settlerbro.chatgpt.site/?auth=callback` и для локальной проверки `http://127.0.0.1:4173/?auth=callback`. Для собственного домена добавить его адрес отдельно.
4. В Google Cloud создать OAuth-клиент типа Web application. В Authorized redirect URIs добавить callback именно проекта Supabase: `https://<project-ref>.supabase.co/auth/v1/callback`. Client ID и Client Secret внести в настройки Google provider в Supabase, а не в код сайта.
5. При тестовом статусе приложения Google добавить тестовые аккаунты в список разрешённых. Проверить согласованный экран Google и необходимые настройки публикации.
6. Проверить полный цикл на отдельном тестовом аккаунте: подтверждение email, вход, восстановление пароля, Google, заполнение анкеты после Google, выход и повторный вход. До подключения проекта эти проверки остаются невыполненными.

Используется локально сохранённый SDK `@supabase/supabase-js` 2.118.0 и PKCE. Приложение не записывает пароль в localStorage, sessionStorage или свою базу `rvb-academy-v1`. SDK управляет своей сессией отдельно. Не запрашиваются дополнительные Google scopes.

## Анкета и доступ

Анкета сотрудника записывается в user_metadata через Supabase Auth: `full_name`, `restaurant_id`, `department`, `position`, `academy_enrollment_requested`. Эти поля редактируемые и не являются источником прав доступа. Выбор «Руководитель» или «Администратор» не выдаёт никаких полномочий.

Пока реализован экран заявки, а не механизм подтверждения менеджером. После входа реальный аккаунт не превращается автоматически в демо-сотрудника и не получает демо-менеджера. До рабочего запуска нужны серверные таблицы заявок/сотрудников/ролей, политика RLS, проверка назначения менеджеров и подключение общей базы обучения. Решения о доступе нельзя принимать по user_metadata.

Текущая приватность Sites сохранена: внешний вход Sites и аккаунт академии — отдельные уровни. После настройки Supabase сайт не станет автоматически доступен всей команде; доступ размещения и собственный домен нужно настроить отдельно с владельцем.
