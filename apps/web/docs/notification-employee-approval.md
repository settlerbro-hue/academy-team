# Одобрение сотрудника из уведомления — 28.10.2026

В уведомлении «Новая заявка сотрудника» добавлены заведение, подразделение, должность и кнопка «Одобрить сотрудника». Сервер присылает возможность действия только для ожидающей заявки сотрудника в текущей области управления. Владелец и операционный директор сохраняют свои области; управляющие — свой бренд; Админ подразделения — свою команду.

Кнопка вызывает `academy_approve_enrollment_notice` с ID уведомления. Метод проверяет владельца уведомления, точный тип события, актуальную видимость, состояние и роль сотрудника, существующие права управления. Для активации используется прежний `academy_manage_member`; роль остаётся `employee`. Чужой ID уведомления, обычное командное событие, чужая область и заблокированный аккаунт не принимаются.

После успеха уведомление отмечается прочитанным, показывается «Сотрудник одобрен», обновляются счётчик и данные команды. Во время запроса кнопка блокируется. Повторный запрос к уже активному сотруднику безопасно возвращает `already_active` без повторного изменения роли. Самих сотрудников эта миграция не одобряет.

Проверки:

- Полный набор проверок приложения прошёл.
- `test-notification-approval.cjs`: данные карточки и экранирование, блокировка повторного клика, один запрос, сообщение об успехе, прочитанное состояние и обновление команды. Клиент не передаёт роль или ID сотрудника.
- `test-notification-approval.sql` в транзакции с откатом: местный Админ, обычный сотрудник, владелец, операционный директор, управляющий «90-е» (все три заведения и запрет РВБ), чужое уведомление, повторный запрос, устаревшая заявка и подмена типа события. Все временные аккаунты, назначения, уведомления и результаты откатились.

После применения миграции повторить серверную проверку можно через `BEGIN;` и `scripts/test-notification-approval.sql`, заканчивающийся `ROLLBACK`.
