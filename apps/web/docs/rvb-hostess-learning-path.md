# Путь хостес РВБ

Семь этапов для активного сотрудника РВБ Минск, подразделение «Зал», должность «Хостес». Владелец и операционный директор с профилем РВБ Минск могут выбрать «Хостес» для предпросмотра. В предпросмотре собственные результаты не выдаются за прогресс хостес.

1. `welcome-90` — общий welcome-курс команды двух брендов.
2. `guru-43403` — правила сотрудника.
3. `hostess-standards` — девять занятий и два теоретических теста (`94441`, `104557`). В маршруте статус «Теория пройдена» отделён от письменного задания по рассадке. Сам исходный курс и его идентификаторы сохранены.
4. `rvb-hostess-practice` — четыре учебные ситуации с письменными заданиями: встреча и ожидание, телефонная бронь, сложная ситуация с бронью, передача гостей официанту. Дополнительно учитывается прежнее задание по рассадке `104548`; его прежние сданные результаты принимаются. Практика содержит пять проверяемых работ, четыре из которых новые. При первом открытии этапа сотрудник попадает в существующее задание по рассадке; если оно уже сдано или ожидает проверки — в новый практический курс.
5. `rvb-waiter-kitchen-menu` — меню кухни РВБ, 11 разделов и 11 тестов.
6. `rvb-waiter-bar-menu` — меню бара РВБ, восемь разделов и восемь тестов.
7. Сводка обязательных тестов и практики — серверный список общей учебной готовности, упорядоченный по занятиям маршрута. В текущей программе 28 проверок, из них пять письменных.

Курсы меню переиспользуются вместе с официантами. Их видимые названия теперь «Меню кухни РВБ» и «Меню бара РВБ», аудитория — прежние должности плюс хостес. Прежние ID, уроки, тесты, ключи ответов и прогресс не меняются. Для хостес меню имеет приоритет `start`; приоритеты официантов сохранены. Названия тестов меню убирают привязку только к официанту. В общих стандартах нейтрализован заголовок скрипта и упоминание бренда в вопросе о внешнем виде без изменения вариантов ответов и ключей.

Письменные работы получают `needs_review=true`. Отправка, ожидание проверки и отклонённый ответ не завершают практику. Администратор своей команды проверяет каждую работу существующим механизмом: 0 — доработать, 1 — принято; комментарий сохраняется в результате. Повторная отправка создаёт новую попытку, предыдущая остаётся в истории. Критерии работы доступны сотруднику в уроке и вопросе.

Для рассадки используется фактическая схема своего зала; номера столов, вместимость, условия бронирования и сроки ожидания не выдумываются. Сценарии не создают реальных броней и не требуют контактов реальных гостей.

Новая практика имеет область `minsk / Зал`. Правила чтения, загрузки, редактирования, проверки работ и роли не расширяются. Пособие и профессиональные ТТК подразделения «Бар» остаются вне доступа обычной хостес. Новые правила устной аттестации или автоматического назначения уровня «Аттестованный» для хостес не вводятся. Программа официанта с 47 проверками и правилом трёх аттестаций сохранена.

## Развёртывание

Однократный контентный импорт: `supabase/seed-rvb-hostess-training.sql`. Он создаёт один курс и четыре письменных задания, обновляет аудиторию существующих курсов меню. При повторном запуске новые практические материалы не перезаписываются. Дальнейшее содержание редактируется штатным редактором.

Генератор: `scripts/build-rvb-hostess-training.cjs`; снимок исходных стандартов и общих курсов — `supabase/sources/rvb-hostess-live-20261027.json`. Учебные данные и SQL остаются в приватном репозитории, публичный `out/` их не содержит.

Проверки: `scripts/test-rvb-hostess-training.cjs` и `scripts/test-rvb-hostess-training.sql`. Серверная проверка выполняет обучение, отправку пяти работ, отказ чужого администратора, доработку и принятие своей командой, проверяет 47 тестов официанта и изоляцию «90-е». Все проверочные изменения откатываются через `ROLLBACK`.
