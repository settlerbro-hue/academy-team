# Академия команды · 90-е и Руки Вверх Бар

Рабочий сайт: [askacademy.ru](https://askacademy.ru). Учётные записи, права и учебные данные хранятся в Supabase.

Приватный проект сайта обучения сотрудников и кабинетов менеджеров четырёх заведений.

## Продолжить разработку на другом ПК

1. Войдите в GitHub под аккаунтом settlerbro-hue.
2. Склонируйте репозиторий или скачайте Code → Download ZIP и распакуйте.
3. Откройте папку проекта в Codex или редакторе. Нужен Node.js 22 или новее.
4. Выполните из корня: `npm run dev` (без npm: `node apps/web/scripts/preview.cjs`).
5. Откройте http://127.0.0.1:4173/ и войдите в свой аккаунт академии.

Установка зависимостей не требуется. Подробности: [DEVELOPMENT.md](apps/web/DEVELOPMENT.md).

## Структура

- apps/web/secure-dist — рабочий frontend, авторизация и защищённые кабинеты.
- apps/web/supabase — миграции, серверные проверки, исходные данные переноса.
- apps/web/dist — архив прототипа и исходные фото, документы и видео.
- documents — оригиналы брендбуков и меню.
- docs — описание архитектуры и результаты проверок.

## Проверка и публикация

Из корня репозитория:

```sh
npm run check
npm run build
```

Первая команда запускает полный набор проверок веб-приложения. Вторая формирует безопасный каталог `out` в корне. Публикуется только `out`; `dist`, `documents`, SQL, SSH-ключи и ключи ответов тестов не должны попадать в публичную сборку.

### Автопубликация на VPS

Workflow [Deploy](.github/workflows/deploy.yml) запускается после каждого push в `main`: проверяет приложение, собирает `out` и отправляет его на сервер `80.64.31.169` под пользователем `deploy`. При неуспешной проверке или сборке отправка на сервер не выполняется.

Для подключения нужен секрет репозитория `DEPLOY_KEY`: приватный SSH-ключ, соответствующий публичному ключу, установленному для пользователя `deploy` на сервере. Ключ хранится в **Settings → Secrets and variables → Actions**, не в файлах репозитория.

Результат доступен во вкладке **Actions → Deploy**. Повторный запуск — **Run workflow** или новый push в `main`. Статус `success` подтверждает завершение отправки файлов; после обновления проверьте сайт в браузере.

Передача через `rsync --delete` синхронизирует содержимое `out` с каталогом, настроенным для SSH-пользователя `deploy`: устаревшие файлы из этого каталога удаляются. Пользователь `deploy` должен быть ограничен каталогом сайта; база данных и Supabase Storage в эту синхронизацию не входят.

База: Supabase ivlinbwuudxyjaikwaoo. Аккаунты, права, результаты и опубликованные файлы остаются в общей базе. Локальные изменения через интерфейс также затрагивают её. Для экспериментов со схемой используйте отдельный тестовый проект. Не запускайте seed и bootstrap повторно поверх рабочей базы без резервной копии и проверки.

Временные сессии, пароли, секретные ключи и кеши инструментов не переносятся. Эта копия не заменяет резервное копирование текущей базы и Storage.
